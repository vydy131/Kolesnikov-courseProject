# Описание прецедентов

## Прецедент UC-001: Регистрация пользователя

**ID:** UC-001
**Название:** Регистрация пользователя
**Акторы:** Инвестор (инициатор), Система (исполнитель)
**Уровень:** Основной функционал

### 1. Краткое описание

Пользователь создает учетную запись в системе агрегатора инвестиционных счетов, указывая email и пароль.

### 2. Предусловия

- Пользователь не авторизован
- Email не зарегистрирован в системе
- Система доступна

### 3. Постусловия

- Создан новый пользователь
- Пользователю отправлено письмо подтверждения email
- Пользователь получает статус PENDING
- Запись о регистрации сохранена в журнале аудита

### 4. Основной поток

1. Пользователь выбирает опцию «Регистрация»
2. Система отображает форму регистрации
3. Пользователь вводит:
   - Email
   - Пароль
   - Подтверждение пароля
4. Пользователь принимает пользовательское соглашение
5. Пользователь нажимает кнопку «Зарегистрироваться»
6. Система выполняет валидацию:
   - Проверяет корректность email
   - Проверяет сложность пароля
   - Проверяет совпадение паролей
   - Проверяет уникальность email
7. Система создает учетную запись пользователя
8. Система генерирует уникальный ID пользователя
9. Система отправляет письмо подтверждения email
10. Система сохраняет пользователя в базе данных
11. Система отображает сообщение об успешной регистрации
12. Система предлагает подтвердить email

### 5. Подпотоки

#### 5.1. Подпоток A: Регистрация через OAuth

- A1. На шаге 1 пользователь выбирает «Войти через Google»
- A2. Система перенаправляет на страницу OAuth-провайдера
- A3. Пользователь подтверждает вход
- A4. Система получает данные пользователя
- A5. Продолжение с шага 7 основного потока

### 6. Потоки исключений

#### 6.1. Исключение E1: Email уже используется

- E1.1. На шаге 6 система обнаруживает существующий email
- E1.2. Система отображает сообщение об ошибке
- E1.3. Пользователь вводит другой email
- E1.4. Продолжение с шага 5

#### 6.2. Исключение E2: Некорректный пароль

- E2.1. На шаге 6 пароль не проходит проверку сложности
- E2.2. Система отображает требования к паролю
- E2.3. Пользователь исправляет пароль
- E2.4. Продолжение с шага 5

#### 6.3. Исключение E3: Ошибка отправки email

- E3.1. На шаге 9 сервис отправки недоступен
- E3.2. Система создает пользователя без подтверждения
- E3.3. Система предлагает повторно отправить письмо позже

**Приоритет:** Высокий
**Частота использования:** 100+ раз в день
**Сложность:** Низкая

## Прецедент UC-002: Подключение брокерского счета

**ID:** UC-002
**Название:** Подключение брокерского счета
**Акторы:** Инвестор (инициатор), Брокер API (внешняя система), Система (исполнитель)
**Уровень:** Основной функционал

### 1. Краткое описание

Пользователь подключает брокерский счет через API брокера для синхронизации активов и операций.

### 2. Предусловия

- Пользователь авторизован
- Брокер поддерживается системой
- API брокера доступно

### 3. Постусловия

- Счет подключен к системе
- Выполнена первичная синхронизация
- Создана запись инвестиционного счета
- Пользователь уведомлен об успешном подключении

### 4. Основной поток

1. Пользователь открывает раздел «Подключить брокера»
2. Система отображает список доступных брокеров
3. Пользователь выбирает брокера
4. Система отображает форму подключения
5. Пользователь вводит API-ключи или проходит OAuth-авторизацию
6. Пользователь подтверждает подключение
7. Система отправляет запрос брокеру
8. Брокер подтверждает доступ
9. Система получает:
   - Список счетов
   - Балансы
   - Активы
   - Историю операций
10. Система создает инвестиционный счет
11. Система запускает синхронизацию данных
12. Система отображает статус «Подключено»

### 5. Подпотоки

#### 5.1. Подпоток A: Подключение нескольких счетов

- A1. На шаге 9 брокер возвращает несколько счетов
- A2. Система отображает список найденных счетов
- A3. Пользователь выбирает нужные счета
- A4. Система подключает выбранные счета

### 6. Потоки исключений

#### 6.1. Исключение E1: Неверные API-ключи

- E1.1. На шаге 8 брокер отклоняет авторизацию
- E1.2. Система отображает сообщение об ошибке
- E1.3. Пользователь повторно вводит ключи
- E1.4. Продолжение с шага 6

#### 6.2. Исключение E2: Брокер недоступен

- E2.1. На шаге 7 API брокера не отвечает
- E2.2. Система отображает сообщение о недоступности
- E2.3. Система предлагает повторить позже
- E2.4. Прецедент завершается неудачей

#### 6.3. Исключение E3: Частичная синхронизация

- E3.1. На шаге 9 получены неполные данные
- E3.2. Система помечает счет статусом SYNC_ERROR
- E3.3. Система уведомляет пользователя
- E3.4. Система автоматически повторяет синхронизацию

**Приоритет:** Высокий
**Частота использования:** 10-50 раз в день
**Сложность:** Высокая

## Прецедент UC-003: Просмотр аналитики портфеля

**ID:** UC-003
**Название:** Просмотр аналитики портфеля
**Акторы:** Инвестор (инициатор), Система (исполнитель)
**Уровень:** Основной функционал

### 1. Краткое описание

Пользователь просматривает сводную аналитику по всем подключенным брокерским счетам.

### 2. Предусловия

- Пользователь авторизован
- Подключен минимум один брокерский счет
- Данные успешно синхронизированы

### 3. Постусловия

- Пользователь получает актуальную аналитику
- Система фиксирует факт просмотра отчета
- При необходимости формируется кэш аналитики

### 4. Основной поток

1. Пользователь открывает раздел «Портфель»
2. Система загружает данные счетов
3. Система агрегирует данные по всем брокерам
4. Система рассчитывает:
   - Общую стоимость портфеля
   - Доходность
   - Распределение активов
   - Уровень риска
5. Система получает актуальные рыночные данные
6. Система формирует аналитический отчет
7. Система отображает:
   - Графики доходности
   - Структуру портфеля
   - Изменения стоимости
   - Риски
8. Пользователь анализирует данные
9. Пользователь может экспортировать отчет

### 5. Подпотоки

#### 5.1. Подпоток A: Экспорт отчета

- A1. На шаге 9 пользователь выбирает «Экспорт»
- A2. Система предлагает формат PDF или Excel
- A3. Пользователь выбирает формат
- A4. Система формирует файл
- A5. Система предоставляет файл для скачивания

### 6. Потоки исключений

#### 6.1. Исключение E1: Нет подключенных счетов

- E1.1. На шаге 2 система не находит счета
- E1.2. Система предлагает подключить брокера
- E1.3. Выполняется UC-002

#### 6.2. Исключение E2: Данные устарели

- E2.1. На шаге 5 рыночные данные устарели
- E2.2. Система запускает обновление
- E2.3. Система отображает индикатор загрузки
- E2.4. После обновления продолжается выполнение

#### 6.3. Исключение E3: Ошибка генерации отчета

- E3.1. На шаге 6 происходит ошибка расчета
- E3.2. Система записывает ошибку в журнал
- E3.3. Система отображает сообщение пользователю
- E3.4. Прецедент завершается неудачей

**Приоритет:** Высокий
**Частота использования:** Многократно ежедневно
**Сложность:** Средняя

## Прецедент UC-004: Создание торговой заявки

**ID:** UC-004
**Название:** Создание торговой заявки
**Акторы:** Инвестор (инициатор), Брокер API (внешняя система), Система (исполнитель)
**Уровень:** Основной функционал

### 1. Краткое описание

Пользователь создает заявку на покупку или продажу актива через подключенного брокера.

### 2. Предусловия

- Пользователь авторизован
- Подключен брокерский счет
- На счете достаточно средств или активов
- Брокер доступен

### 3. Постусловия

- Создана торговая заявка
- Заявка отправлена брокеру
- Получен статус исполнения
- Операция сохранена в журнале

### 4. Основной поток

1. Пользователь открывает раздел торговли
2. Система отображает список активов
3. Пользователь выбирает актив
4. Пользователь выбирает тип операции:
   - BUY
   - SELL
5. Пользователь вводит:
   - Количество
   - Цену
6. Система отображает предварительный расчет
7. Пользователь подтверждает заявку
8. Система выполняет проверку:
   - Достаточность средств
   - Корректность параметров
   - Доступность брокера
9. Система создает заявку
10. Система отправляет заявку брокеру
11. Брокер подтверждает получение
12. Система отображает статус заявки

### 5. Подпотоки

#### 5.1. Подпоток A: Рыночная заявка

- A1. На шаге 4 пользователь выбирает «Market Order»
- A2. Система автоматически подставляет рыночную цену
- A3. Продолжение с шага 6

### 6. Потоки исключений

#### 6.1. Исключение E1: Недостаточно средств

- E1.1. На шаге 8 проверка не пройдена
- E1.2. Система отображает сообщение
- E1.3. Пользователь изменяет параметры
- E1.4. Продолжение с шага 5

#### 6.2. Исключение E2: Брокер отклонил заявку

- E2.1. На шаге 11 брокер возвращает ошибку
- E2.2. Система отображает причину отказа
- E2.3. Заявка получает статус FAILED

#### 6.3. Исключение E3: Потеря соединения

- E3.1. На шаге 10 теряется соединение
- E3.2. Система переводит заявку в статус PENDING
- E3.3. Система автоматически повторяет отправку
- E3.4. Пользователь получает уведомление

**Приоритет:** Высокий
**Частота использования:** Ежедневно
**Сложность:** Высокая
